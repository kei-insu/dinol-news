| 최종 갱신 | 변경 |
|---|---|

> **이 문서를 세션 시작 시 읽는다.** raw: `https://raw.githubusercontent.com/kei-insu/dinol-news/astro/docs/howto/briefing-deploy.md`

## 이 세션의 역할

**브리핑 검증과 배포만** 다룬다.

| 이 세션이 하는 것 | 이 세션이 하지 않는 것 |
|---|---|
| `validate.py` 게이트 통과 확인 | 카드 교체 · 기사 크롤링 · 카드 본문 작성 |
| 구성 균형 수동 검증(③) | 문서 구조 정비 · 규칙 개정 |
| 화면 확인 절차 안내 | Firestore 마이그레이션 · Astro 전환 |
| 대장 재생성 → 배포 명령 안내 | |
| 노션 작업 일지 기입 | |
| (선택) astro 후속 — 병합·카드 추출·소스 동기화 | |

**카드 교체는 루틴이 담당한다.** 루틴이 만든 초안을 받아 검증하고 내보내는 것이 이 세션의 일이다.

검증에서 문제가 나오면 **고치지 말고 보고한다.** 다만 **필드 누락·형식 오류처럼 내용 판단이 필요 없는 결함**은 이 세션에서 고쳐도 된다(em대시 치환 등, ③ 아래 「수정 가능 범위」 참조).

---

## 작업 순서

```
①  브랜치 확인      git status -sb            → main 이어야 함
②  사전 검증        validate.py               → ERROR 0건
③  구성 균형 확인   수동 13항목 (아래 체크리스트)
④  화면 확인        localhost:8000
⑤  대장 재생성      build_published_urls.py
⑥  롤백 지점        git fetch → git rev-parse origin/main
⑦  배포             deploy.ps1
⑧  반영 확인        commit-pinned raw URL
⑨  노션 작업 일지   1행
```

**명령은 한 번에 하나씩** 제시하고 실제 출력을 받은 뒤 다음으로 간다.
**커밋·배포 실행은 인수님이 직접 한다.** 명령을 제시하고 실행을 대신하지 않는다.

## ② 사전 검증 — 필수 게이트

### [터미널-운영]
```powershell
python scripts\validate.py news\2026\MM\Dinol_news_YYYYMMDD.html
```

**ERROR 0건이어야 발행한다.** WARN은 사유를 보고에 남기고 진행 가능.

`validate.py`는 HTML 원문을 직접 읽으므로 브라우저 캐시·에셋 버전의 영향을 받지 않는다. **브라우저 화면보다 이 결과가 먼저다.**

> ⚠️ main과 astro의 `validate.py` 버전이 다르다. main에는 `validation_common.py`가 없어 카테고리 canonical 검사 등 일부 규칙이 돌지 않는다. 그래서 ③ 수동 확인이 필요하다.

**③에서 파일을 고쳤으면 ②를 다시 돌린다.** HTML 속성 구조가 깨지지 않았는지 확인하는 목적이다.

## ③ 구성 균형 확인 — 수동 13항목

`validate.py`가 잡지 못하는 항목이다. **브리핑 HTML과 `scripts/source_rules.json`을 함께 받아** 8장을 표로 뽑아 확인한다.

| # | 항목 | 통과 조건 |
|---|---|---|
| 1 | 카드 수 | AI 4 + Design 4 |
| 2 | 지역 비율 | **각 섹션 국내 2 · 해외 2** |
| 3 | 매체 상한 | 동일 매체 **AI·Design 전체 합산 2건 이하** |
| 4 | 계열 합산 | 디자인플러스·헤이팝·행복이 가득한 집 = 디자인하우스 1개로 계산 |
| 5 | 그라디언트 | **8장 전부 다른 색** |
| 6 | featured | 각 섹션 첫 카드 1장씩, 총 2장 |
| 7 | 카테고리 | AI 카드 `AI · ` / Design 카드 **`디자인 · `** 로 시작. `Design · `은 위반 |
| 8 | EN 카드 | `data-category-en` · `data-title-en` · `-kr` 짝 5종 존재 |
| 9 | em대시 | 카드 본문에 `—` **0건** (`<title>`·주석·검증 지침은 대상 아님) |
| 10 | 별점 | AI 섹션 ★4~5 최소 1장 |
| 11 | **전체 ★5** | **최소 1장** (`policy.md §7-1` 방법론·툴 사용법 0순위). **10번과 별개 지표다** — ★4가 늘어도 ★5는 안 나올 수 있다 |
| 12 | 게재일 | 수집 기간(1주) 내인지. 초과 시 목록 보고 |
| 13 | **매체 등록** | 카드 8장 출처가 `source_rules.json` 에 전부 있는지 **전수 대조** |

**지역 판정은 기사 언어가 아니라 원문 발행 매체의 국적이다.** `ZDNet Korea` = 국내 / `TechCrunch` = 해외.

**계열 합산은 `docs/reference/news_sources.md`에 명시된 것만 적용한다.** 문서에 없는 계열을 즉석 판단하지 않는다.

### 11번·13번이 왜 추가됐나

| 항목 | 사고 |
|---|---|
| 전체 ★5 | 2026-08-11 배포에서 이 조건을 몰라 놓쳤고, 다음 날 `daily_import.py [5]` 가 배포 **후에** 잡았다. 8/10은 ★5가 우연히 있어 통과했던 것이다 |
| 매체 등록 | 2026-08-12 에 국내 신규 매체만 눈으로 훑고 `Adobe Blog` 를 놓쳐 `daily_import.py` 를 2회 실행했다. 눈이 아니라 **대조**로 한다 |

13번은 배포를 차단하지 않는다. 다만 여기서 잡으면 astro 추출 시 게이트 `[1]` 이 1회에 통과한다(8/13~8/16 4일 연속 확인).

### 게재일 판정 기준 (12번)

| D값 | 처리 |
|---|---|
| 1주 이내 | 통과 |
| 1주 초과 ~ 수십 일 | **예외 승인 가능** — 에버그린(방법론·포트폴리오·트렌드 캘린더·디자인 시스템)이면 승인, 시의성 콘텐츠(제품 출시·AI 툴)면 교체 검토 |
| **D-365 이상** | **반려.** 예외 승인 대상이 아니다 |

승인·반려 모두 **사용자 판단**이다. Claude는 목록과 판단 근거를 제시하고 결정을 받는다.

**반려 시 교체 제약을 함께 전달한다** — 섹션 · 지역(비율 유지) · 기존 7개 매체와 중복 없음 · 그라디언트(기존 색 유지 또는 미사용 색) · 게재일. 교체본을 받으면 **②부터** 다시 돈다.

### 수정 가능 범위

| 결함 | 처리 |
|---|---|
| em대시, 필드 누락, 형식 오류 | **이 세션에서 수정.** 단 영문 문장의 대체 부호 선택은 치환안을 먼저 제시하고 승인받는다. 수정 후 ② 재실행 |
| 주제 부적합 · 게재일 반려 · 별점 편중 | **보고만.** 루틴 재실행 소관 |

## ④ 화면 확인

### [터미널-운영]
```powershell
python -m http.server 8000
```

→ `http://localhost:8000/news/2026/MM/Dinol_news_YYYYMMDD.html`

| 확인 | 정상 |
|---|---|
| 노란 「⚠ 링크 없음」 배지 | 없음 |
| 하단 빨간 배너 | 없음 |
| F12 콘솔 | `✅ 콘텐츠 검토 통과` |
| 디놀 톡톡 | 기존 글 목록 표시 |

**`file://`로 열지 않는다.** `dinol-firebase.js`가 ESM 모듈이라 CORS로 차단되어 좋아요·톡톡이 뜨지 않는다.

**브랜치가 main인지 반드시 확인한다.** astro에서 열면 카드 구조 불일치로 「⚠ 링크 없음」 배지 8개 + 빨간 배너가 뜬다. **파일 결함이 아니라 환경 오탐이다.**

카드를 교체했거나 처음 쓰는 그라디언트가 있으면 **해당 카드 드로어를 열어 눈으로 확인한다.**

## ⑤~⑦ 대장 재생성 → 배포

### [터미널-운영]
```powershell
python scripts\build_published_urls.py
```

브리핑 수 +1, 고유 URL +8이어야 정상. 중복 URL 4건(7월 발행분끼리)은 기존 이력이며 **5건 이상이면 멈추고 보고한다.**

### [터미널-운영]
```powershell
git status --short
```

판정: 브리핑 HTML(`??`) · `index.json`(`M`) · `published_urls.json`(`M`) **3건만**. 다른 항목이 뜨면 멈추고 보고한다. `deploy.ps1`은 `git add -A`라 화면에 뜬 게 전부 올라간다.

### [터미널-운영]
```powershell
git fetch origin
```

### [터미널-운영]
```powershell
git rev-parse origin/main
```

**출력 해시를 롤백 지점으로 기록한다.** 이 값이 노션 작업 일지 `이전커밋` 필드에 들어간다. 기록 없이 배포하지 않는다 — main은 GitHub Pages 빌드 대상이다.

### [터미널-운영]
```powershell
./deploy.ps1 "content: M/D 브리핑 발행 (AI 4 + Design 4)"
```

`[4/6]` validate 출력의 한글이 CP949로 깨지는 것은 정상이다. **종료 코드(`exit=0`)가 판정 기준이다.**

## ⑧ 반영 확인

**브랜치 raw URL을 쓰지 않는다.** CDN 캐시로 최대 5분 stale이라 옛 버전이 나온다. **commit-pinned raw URL**로 조회한다.

```
https://raw.githubusercontent.com/kei-insu/dinol-news/<커밋해시>/news/2026/MM/Dinol_news_YYYYMMDD.html
```

`index.json` 최상단에 오늘 날짜가 들어갔는지도 함께 확인한다.

## (선택) astro 후속 — 카드 추출

배포가 끝난 뒤 이어서 할 수 있다. **매체 등록이 없으면 3단계로 끝난다.**

```
① git merge main          충돌 0건이어야 정상(매일 병합하면 브리핑 3파일만 들어온다)
② 판정값 파일 저장         scripts/daily/{ymd}.json
③ daily_import.py {ymd}   게이트 [0]~[10] 전수 통과
④ 커밋                    카드 8 + 판정값 1 (+ source_rules.json)
⑤ 3사본 동기화 (필요 시)   news_sources.md · routine_instruction.md §3 · 루틴 UI
```

### 판정값 파일

`category_kr` · `impactScore` · `positions` 는 **브리핑 HTML 속성에서 그대로 온다.** `category_en` 만 KR 카드에서 작문이 필요하다(매일 4건 안팎). 전달 전 HTML 값과 대조 검증한다.

### 게이트 [0] 제약

허용 변경은 **`scripts/daily/{ymd}.json` · `scripts/source_rules.json` 2개뿐**이다. `staged` 상태도 차단하므로 `git add` 로는 빠지지 않는다.

**`docs/` 변경(3사본 동기화)은 추출을 끝낸 뒤에 저장한다.** 먼저 저장했다면 `docs/` 만 별도 커밋해 분리한다.

### 매체 등록

| 유형 | 처리 |
|---|---|
| 공식 블로그 (`Adobe Blog`·`Figma Blog`·`Google`·`Anthropic` 등) | 1차 소스. `source_rules.json` 에만 등록, 4항목 판정·3사본 동기화 불필요 |
| 약어 표기 (`NN/g`) | `group` 에 풀네임을 넣어 **별칭 등록**. `source.name` 은 카드 표기 유지, 매체 상한 계산만 합산된다 |
| 신규 언론 매체 | **4항목 판정** — ①기자 서명 ②보도자료 전재 여부 ③1차 소스 인용 ④분야 전문성 |

**4항목 판정 결과는 3단으로 나뉜다.**

```
전부 통과   → 무조건부 등록
④만 미달    → 조건부 등록 (제약 조건을 비고에 명시)
전부 미달    → 제외 (news_sources.md 「제외 매체」)
```

⚠️ **미등록 건수가 곧 신규 매체 수는 아니다.** 8/13은 4건 중 2건, 8/16은 4건 중 3건이 `news_sources.md` 에 이미 있던 표기 격차였다. **3사본 동기화 전에 `news_sources.md` 를 약어·영문·한글로 교차 검색한다.**

## 알려진 함정

| 항목 | 내용 |
|---|---|
| CDN 캐시 | 브랜치 raw URL 최대 5분 stale. commit-pinned로 확인 |
| PowerShell 5.1 | `&&` 미지원. 명령을 한 줄씩 분리 |
| astro 오탐 | astro에서 브리핑을 열면 「링크 없음」 배지 8개. 파일 결함 아님 |
| `file://` | Firebase ESM CORS 차단. 반드시 `http://localhost:8000` |
| validate.py 버전 | main 버전은 일부 규칙이 없다. ③ 수동 확인으로 보완 |
| deploy.ps1 | `git add -A`. 실행 전 `git status --short`로 범위 확인 필수 |
| deploy.ps1 push | main은 `[6/6]`에서 **자동 push된다.** astro만 수동 판단 대상 |
| 파일 업로드 | 인수님이 올린 파일이 **전날 버전일 수 있다.** 편집 전 버전 지문(종수·줄수·직전 세션 추가분)을 찍는다 |
| 출력 깨짐 | `daily_import.py` 출력에 키릴 문자·구간 누락이 보이면 **파일 수정 전에 재실행해 대조**한다. 터미널 문제인 경우가 있다 |
| OneDrive 잠금 | 저장소가 OneDrive 폴더에 있어 `git` 이 폴더 삭제에 실패할 수 있다. 위험 작업 전 동기화 일시 중지 |

## 보고 형식

**검증 결과**

```
validate.py : ERROR N건 · WARN N건
구성 균형   : AI 2:2 · Design 2:2 / 매체 상한 준수 / 그라디언트 8종 고유
             / em대시 0 / 전체 ★5 N장 / AI high45 N · Design high45 N
             / 매체 등록 미등록 N건
```

**배포 완료 보고** — 커밋 해시 / 변경 파일 / push 여부 / 반영 확인 결과 / **범위 외 변경 없음 확인**

**파일 전달 시** — 다운로드 링크 **바로 위**에 헤딩으로 경로 표기. 사이에 다른 문장을 넣지 않는다.

```
### 📁 저장 경로 — dinol-news > news > 2026 > MM 폴더
```

- **카드를 교체하지 말 것.** 주제 부적합·게재일 반려·별점 편중은 보고만 하고 루틴 재실행으로 넘긴다
- 실행하지 않은 명령의 출력이나 열지 않은 파일의 내용을 지어내지 말 것
- 문서 구조 정비·규칙 개정을 이 세션에서 시작하지 말 것
- 브리핑과 무관한 파일을 커밋 범위에 넣지 말 것
- 롤백 지점 기록 없이 배포하지 말 것
- 검증 없이 "완료"라고 하지 말 것. 종료 코드·출력 구간을 증거로 제시한다
- 한 번에 2개 이상의 작업을 동시에 진행하지 말 것
- **파일 편집 후 검증 출력을 확인하지 않고 넘어가지 말 것.** 앵커 문자열 불일치로 편집이 조용히 실패할 수 있다
