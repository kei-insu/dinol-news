## 7. 콘텐츠 편집 정책 — 2026-07-26

브리핑 카드의 별점, 필드 작성, 관련 직무 부여 기준을 정의한다.
상세 페이지 데이터 구조와 `contentId` 규칙은 `detail-page-schema.md` 를 단일 기준으로 따른다.
선별 절차(구성 균형·매체 상한·후보 풀)는 `routine_instruction.md` §3-1 을 따른다.

### 7-1. 섹션별 실무 영향도 기준 (data-impact-score)

`data-impact-score`(★1~5)는 **디자이너 독자가 자기 실무에 얼마나 직접 적용·참고할 수 있는가**로 채점한다.
임의 부여 금지. 한 브리핑 안에서 2~3에만 몰리지 않게 실제로 분포시킨다.

**AI 섹션과 Design 섹션은 판정 축이 다르다.** 실측(201카드) 결과 AI는 ★1이 45%,
Design은 ★2가 68%로 분포가 구조적으로 달랐다. 단일 루브릭을 쓰면 양쪽이 한쪽으로 쏠린다.

**AI 섹션 — 실무 접점 거리**

| ★ | 기준 | 예 |
|---|---|---|
| 5 | 디자이너가 직접 쓰는 툴의 사용법·신기능 | 피그마 신기능, 생성형 이미지 툴 사용법 |
| 4 | 제작 워크플로를 바꾸는 기술 | 영상 생성 툴, 에이전트 자동화 |
| 3 | 도구 지형 변화 | 모델 출시, 요금 개편, 벤치마크 |
| 2 | 창작 생태계·직업 환경 변화 | 저작권 판결, AI 음원 비중, 일자리 |
| 1 | 배경 맥락 | 정책·반도체·투자·M&A |

**Design 섹션 — 추출 가능성**

| ★ | 기준 | 예 |
|---|---|---|
| 5 | 방법론·프로세스·시스템 공개 | 로고 트렌드 리포트, 타이포 매뉴얼 |
| 4 | 결과물 + 구조 설명 | 리브랜딩, BX 시스템, 패키지 리뉴얼 |
| 3 | 흐름·역할 변화 | 트렌드, 디자이너 역할 이동 |
| 2 | 완성작 감상 | 건축, 제품, 전시 |
| 1 | **미사용** | 디자인 기사인데 실무 무관이면 선별 오류 |

- **Design 섹션은 ★1을 쓰지 않는다.** 실측 201카드에서 0건이었다.
- 디자인 방법론·툴 사용법은 원칙적으로 ★4~5.
- 지역 균형을 맞추려고 별점을 부풀리지 않는다.

### 7-2. 섹션별 필드 작성 기준

AI 기사는 기술·산업 정보를 **디자인 언어로 번역**해야 하고,
Design 기사는 이미 디자인 언어이므로 **가져올 요소를 추출**하면 된다.
이 차이는 별점만이 아니라 모든 필드에 적용된다.

| 필드 | AI 섹션 — 번역 | Design 섹션 — 추출 |
|---|---|---|
| 선별 기준 | 디자인 실무로 번역할 가치가 있는 변화 | 형태·구조·과정·방법 중 최소 하나를 말할 수 있는 사례 |
| 한 줄 요약 | 기술 용어를 풀어 변화의 핵심 설명 | 누가 무엇을 어떤 접근으로 설계했는지 |
| 핵심 인사이트 | 주요 사실·수치와 중요한 이유 | 형태·재료·구조·프로세스상의 디자인 결정 |
| 관련 직무 | 기술 변화와 직접 연결되는 직무 | 사례를 직접 참고할 수 있는 직무 |
| 디자인 관점 | 이 기술이 실무의 무엇을 바꾸는지 번역 | 이 사례에서 무엇을 가져올 수 있는지 추출 |
| 실무 영향도 | 디자인 실무와의 접점 거리 | 실무에서 추출·재사용할 수 있는 정도 |
| 활용 추천 | 지금 적용·테스트·주시해야 하는 상황 | 어떤 프로젝트·단계·자료에 참고할지 |
| 큐레이션 노트 | 기술 맥락을 풀고 디자인 시사점으로 확장 | 작업의 의미를 해석하고 다른 사례·흐름으로 확장 |

### 7-3. 관련 직무 정책 (data-position)

**저장은 내부 ID, 표시는 매핑표.** 라벨 표기가 바뀌어도 카드 데이터를 건드리지 않는다.

| 항목 | 값 |
|---|---|
| 속성 | `data-position="editorial-designer\|brand-designer"` (`\|` 구분) |
| 라벨 소스 | `src/lib/positions.ts` 의 `POSITIONS` 맵 |
| 개수 | 기본 1개, 최대 2개 |
| 언어 | 한국어 고정 (`data-position-en` 미생성) |
| 미등록 ID | 화면 미노출 + `console.warn` + 발행 검증 오류 |
| 부여 없음 | 상세 페이지에서 `공통 참고` 기본 칩 표시 (JSON은 빈 배열 유지) |

## 8. 파일 전달 시 저장 경로 표기 (2026-07-25)

파일을 다운로드로 전달할 때 **다운로드 바로 위에 레포 저장 경로**를 표기한다.
형식 `dinol-news > <폴더> 폴더`. 상세 매핑은 `claude.md` 핸드오프 규칙 참조.

| 대상 | 경로 |
|---|---|
| 브리핑 | `dinol-news > news 폴더 > 2026 폴더 > MM 폴더` |
| 문서(.md) | `dinol-news > docs 폴더` |
| 에셋(css/js) | `dinol-news > assets 폴더` |
| 스크립트 | `dinol-news > scripts 폴더` |
| 카드 데이터 | `dinol-news > content 폴더 > news 폴더` |
| 루트 파일 | `dinol-news 루트` |

> 경로는 **폴더를 하나씩 끊어서** 표기한다. `content/news 폴더` 처럼 쓰면 슬래시가 폴더 이름의 일부로 오해된다.
