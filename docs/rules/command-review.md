**8번 — 보고 형식 (2026-08-09 신설)**

Claude Code 지시문 끝에 **상세 결과 보고**를 지시한다. 이 보고는 Claude 만 보는 것이 아니라 GPT 리뷰의 검토 자료다.

**전달 원칙** — 리뷰어가 산출물에 직접 접근할 수 없는 경우, 검토에 필요한 증거를 보고에 포함하거나 리뷰어가 접근 가능한 방식으로 전달한다.

**산출물 유형별 최소 증거**

| 산출물 | 최소 증거 |
|---|---|
| 코드·텍스트 파일 | diff / patch 또는 원문 |
| UI·시각 결과 | 스크린샷 또는 실제 렌더링 결과 |
| DB·데이터 변경 | 변경 전후 값 또는 조회 결과 |
| 실행·테스트·빌드 | 실행한 명령 + 실제 출력 |
| 배포·외부 서비스 | 실제 접근 결과 또는 상태 확인 |
| 공통(필수) | 지시와 어긋난 점이나 예상 밖 발견 |

**증거는 현재 작업 환경에서 직접 확보 가능한 범위에서 제공한다.** 직접 확인할 수 없는 항목은 확인했다고 단정하지 않고, 사용자 육안 확인이나 외부 검증이 필요하다고 보고한다.

**파일 상태별 diff 명령**

| 상태 | 명령 |
|---|---|
| 추적 중인 파일 수정·삭제 | `git diff` |
| 새 파일 | 전체 내용, 또는 stage 가 허용되는 작업이면 `git add` 후 `git diff --cached` |
| stage 가 작업 정책상 허용되지 않을 때 | 파일 전문 |

**새 파일은 일반 `git diff` 에 나오지 않는다.** untracked 상태이기 때문이다.

**검증 목적으로 stage 할 때는 기존 staged 변경과 섞이지 않는지 먼저 확인한다.** 여러 작업이 동시에 진행되는 저장소에서는 새 파일 하나를 검증하려다 무관한 변경까지 리뷰 대상에 섞일 수 있다. `git diff --cached --name-status` 로 대상을 먼저 본다.

**`--stat` 은 규모 확인용이며 내용 검증을 대체하지 않는다.** `--stat` + 임의 발췌만 주면 발췌 밖의 누락·오타를 리뷰어가 볼 수 없다.

**출력이 클 때**

- 리뷰어가 직접 접근 가능한 첨부·공유 산출물이면 파일로 전달한다.
- 그렇지 않으면 검토에 필요한 내용이나 patch 를 보고에 포함한다.
- 대형 파일을 통째로 채팅에 붙이지 않는다. 사용자가 리뷰어에게 무엇을 전달해야 하는지 명시한다.
- 로컬 경로만 알려주는 것은, 리뷰어가 그 경로에 접근할 수 없다면 검토 자료가 아니다.

**상태 마커** — 보고 마지막 줄에 단독으로 쓴다.

| 마커 | 조건 |
|---|---|
| `완료` | 요청한 작업과 검증이 모두 끝남 |
| `중단 — <사유>` | 추가 판단·입력·검증이 필요함 |

`완료` 는 메시지 종료 기호가 아니라 **작업 완료 상태 마커**다. 결정을 기다리는 상태에서 `완료` 를 쓰면 작업 완료와 응답 종료가 혼동된다.

**커밋 여부는 이 규칙에 넣지 않는다.** 해당 작업의 지시를 따른다. 편집만 시키는 작업이면 `커밋하지 않는다`를 별도로 적고, Claude Code 가 커밋까지 해야 하는 작업이면 그 지시를 적는다. 보고 규칙에 `커밋하지 않는다`를 고정하면 커밋 작업 지시문에서 1번 「모순」에 걸린다.

**검증 명령의 위치** — 사용자에게 별도로 실행받을 터미널 검증 명령은 Claude Code 편집 지시와 분리한다. 다만 Claude Code 가 구현 결과를 스스로 검증해야 하는 명령·테스트(빌드·`git diff`·파일 존재 확인 등)는 해당 작업 지시문에 포함할 수 있다.
