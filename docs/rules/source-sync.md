# 소스 목록 동기화 규칙 (2026-08-06)

브리핑 소스 목록은 **세 곳에 사본이 있다. 한 곳만 고치면 다음 세션이 어긋난 사본을 읽는다.**

| # | 위치 | 성격 |
|---|---|---|
| ① | `docs/news_sources.md` | **단일 출처** — 전체 목록·URL·수집 가능 여부 |
| ② | `docs/routine_instruction.md` §3 | **레포 정본** — 매일 도는 목록만 발췌 |
| ③ | 루틴 UI 프롬프트 | **실제 실행본** — 여기를 안 고치면 루틴 동작이 안 바뀐다. ②의 **경계 마커 아래 전체**와 바이트 단위로 같아야 한다 |

- 소스를 추가·삭제하면 **같은 변경에서 세 곳을 함께** 고친다.
- ③은 레포 밖(노션 첨부·루틴 UI)이라 git이 잡아주지 않는다. **반영 여부를 사람이 확인**한다.
- 계열 매체 판정은 ①에 명시된 것만 적용한다. 문서에 없는 계열을 세션마다 즉석 판단하지 않는다.

**2026-08-06 사고 기록** — 루틴 §3이 ①의 일부(해외 5곳)만 담고 있어 EN 소스 고갈이 07-26~08-06 **8일 연속** 발생. 원인은 소스 부족이 아니라 사본 미동기화였다.

**2026-08-07 동기화 완료** — 세 사본의 §3 소스 블록을 문자 단위 일치까지 맞췄다(국내 37 · 해외 58). 이후 드리프트가 나면 ②를 정본으로 보고 ③에 블록을 통째 복사한다. 부분 수정하지 않는다 — 08-06 드리프트 3건이 부분 수정에서 나왔다.
③의 자동 동기화 방안은 노션 백로그에 등록했다.

**2026-08-08 경계 마커 도입** — ②에 `<!-- ===== 여기부터 루틴 UI에 그대로 붙여넣는다 ===== -->` 한 줄을 넣어 문서를 둘로 나눴다. 마커 **위**는 레포 전용(갱신 이력·변경 근거), **아래**가 ③에 들어가는 실행 프롬프트다. ③의 컨텍스트를 약 12%(1,981자) 줄이면서도, 마커 아래가 ③과 바이트 단위로 같아 드리프트를 여전히 diff로 잡을 수 있다. **③을 갱신할 때는 마커 아래 전체를 복사한다.**
