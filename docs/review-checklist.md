## 적용 원칙

- 현재 작업과 직접 관련된 항목만 확인한다.
- 이미 확인·검증한 항목은 다시 요구하지 않는다. 이후 변경으로 영향받은 것만 재검증한다.
- **누락과 과잉을 함께 본다.** 누락을 막으려 불필요한 구현을 추가하지 않고, 과잉을 줄이려 필수 안전장치를 제거하지 않는다.
- 일반적인 모범 사례보다 **이 프로젝트의 실제 구조와 기존 결정**을 우선한다.
- 구현 전에는 명세를, 구현 후에는 **실제 코드와 실행 결과**를 본다.
- **보고서의 주장과 실제 코드가 다르면 코드를 기준으로 판단한다.**

# A. 예외와 조용한 실패

> **사고 ①** `data-title-en` 누락이 검증을 통과해 상용에 2회 나갔다 (7/29·8/1).
> `validate.py`가 EN 카드의 제목 속성을 아예 검사하지 않았다.
>
> **사고 ②** `likeKey()`가 경로에서 날짜를 못 찾으면 **조용히 빈 문자열로 폴백**했다.
> 예외를 던지지 않아 무접두어 문서 35건이 쌓이는 동안 아무도 몰랐다.
>
> **사고 ③** `count: 0` 문서에 취소를 시도하면 규칙 위반이 되는데, 그 분기가 없었다.

- [ ] **필수 값이 없을 때 조용히 넘어가지 않는가** — 빈 문자열·기본값 폴백이 사고를 숨긴다
- [ ] 정상 경로뿐 아니라 **실패 경로가 정의**되어 있는가
- [ ] 데이터가 없거나 0이거나 비정상 타입일 때의 동작이 정의되어 있는가
- [ ] 재실행·중복 실행 시 동작이 정의되어 있는가
- [ ] **일부 단계만 성공했을 때** 어떤 상태가 남는가
- [ ] 오류를 정상으로 오판할 경로가 없는가 (`try/catch`가 실패를 성공값으로 바꾸는지)
- [ ] 검증기가 **그 필드를 실제로 보고 있는가** — 검사 항목에서 빠진 필드가 있는지

# B. 데이터와 식별자

> **사고 ④** 좋아요 키가 원문 URL 기반이었는데 카드 `href`가 상세 URL로 바뀌면서
> 같은 카드인데 다른 키가 생성됐다. 페이지마다 다른 값을 추론한 게 원인이다.

- [ ] 동일 대상을 가리키는 **식별자가 하나로 통일**되어 있는가
- [ ] 값을 **명시적으로 전달**하는가, 페이지·경로·DOM에서 **추론**하는가
  - 추론은 페이지 구조가 바뀌면 조용히 깨진다. 컴포넌트가 전달하고 JS는 받은 값만 쓴다
- [ ] 이전 데이터와 신규 데이터의 **호환 정책**이 있는가
- [ ] 마이그레이션·롤백·재실행이 필요한가
- [ ] 중복이나 충돌 가능성을 **양방향으로** 확인했는가 (A→B 유일 ≠ B→A 유일)
- [ ] 개수만 맞추는 검산인가 — **잘못 든 것과 빠진 것이 상쇄될 수 있다**

---

# C. UI 구조

> **사고 ⑤** `<a class="card">` 안에 좋아요 버튼을 넣으려 했다.
> 앵커 안 인터랙티브 요소는 HTML 위반이고 `stopPropagation()`으로 못 고친다.

- [ ] HTML 구조가 유효한가 — **앵커 안 버튼·버튼 안 앵커**가 없는가
- [ ] 버튼에 `type="button"`이 필요한지 확인했는가
- [ ] 접근 가능한 이름 또는 `aria-label`이 있는가
- [ ] **키보드로 각 요소에 도달·실행**할 수 있는가, 포커스 표시가 보이는가
- [ ] 클릭 영역(pseudo-element 오버레이 등)이 다른 요소를 가리지 않는가
- [ ] 모바일 폭에서 레이아웃이 깨지지 않는가

---

# D. 변경 영향 범위

> **사고 ⑥** `a.card` 셀렉터를 바꿀 때 CSS·JS·검증 스크립트 4종·추출기까지
> 어디에 쓰이는지 모르는 채로 "CSS 한 줄만 바꾸면 된다"고 판단했다.

- [ ] **영향 범위를 추정하지 말고 실측**했는가 — 셀렉터·함수·컴포넌트 사용처 전수
- [ ] 변경으로 영향받는 **검증 스크립트**를 확인했는가
- [ ] 공통 컴포넌트 변경이 다른 페이지에 미치는 영향을 확인했는가
- [ ] 자동 생성 파일과 직접 수정 파일이 구분되어 있는가
- [ ] **변경 전 baseline**을 기록했는가 — 없으면 증감을 판정할 수 없다

# E. 커밋과 배포

> **사고 ⑦** `deploy.ps1`이 브랜치 확인 없이 실행돼 `astro`에 배포 커밋이 들어갔다.
>
> **사고 ⑧** `deploy.ps1`이 `git add -A`를 쓰는데 `.gitignore`에 `__pycache__`가 없어
> `.pyc` 파일이 저장소에 커밋됐다.

- [ ] **현재 브랜치가 맞는가** — 스크립트가 스스로 확인하는가
- [ ] 스테이징 대상을 **파일 단위로 지정**했는가 (`git add -A`는 예상 밖 파일을 담는다)
- [ ] `git diff --cached`로 **실제 커밋 대상**을 확인했는가
- [ ] 사용자가 만든 미추적 파일과 작업 변경을 구분했는가
- [ ] 임시 파일·조사 코드·캐시가 남아 있지 않은가
- [ ] **검증이 끝나기 전에 커밋·배포하지 않는가**
- [ ] 배포 대상 프로젝트·계정이 명확한가, 복수 방어가 있는가
- [ ] 운영 데이터에 쓰기가 발생하지 않는가

# F. 테스트 설계

> **교훈** 규칙 테스트는 **서버가 막는지**만 본다.
> **클라이언트가 애초에 그 요청을 안 보내는지**는 별개다. 둘 다 필요하다.

- [ ] 검증 대상이 **서버 규칙인가 클라이언트 로직인가** — 섞지 않는다
- [ ] mock이 **검증하려는 분기만** 통제하는가 (전체를 실패시키면 그 경로에 못 들어간다)
- [ ] 테스트 간 데이터가 격리되는가
- [ ] 비정상 사전 데이터를 만들 수 있는가 (규칙을 통과 못 하는 상태는 우회 생성 필요)
- [ ] **실행할 수 없는 테스트를 통과로 보고하지 않는가**
- [ ] 실행 환경(런타임·버전)이 준비되어 있는가
- [ ] 플레이스홀더가 아닌 **실제 실행 가능한 명령**인가
- [ ] 자동으로 확인 못 하는 것만 **사용자 육안 검증**으로 남겼는가
- [ ] 육안 검증 항목이 **구체적**인가 ("기존 외형 유지" 같은 모호한 기준 금지)

# G. 과잉 방지

> **사고 ⑨** 5-A-2 명세가 12회 이상 왕복하며 계속 커졌다.
> 매번 항목이 늘기만 하고 줄어든 적이 없었다.

- [ ] 요청하지 않은 기능이 추가되지 않았는가
- [ ] **후속 단계 작업을 현재 필수 조건으로** 만들지 않았는가
- [ ] 기존 구조 안에서 해결 가능한 문제인가
- [ ] 한 번만 쓸 인터페이스·추상화를 만들지 않았는가
- [ ] **테스트 때문에 운영 코드가 복잡해지지** 않았는가
- [ ] 이미 통과한 검증을 다시 요구하지 않는가
- [ ] **검증 체계가 구현 규모보다 커지지** 않았는가
- [ ] 일회성 조사 코드를 저장소에 남기지 않는가
- [ ] 작업 중 임시 문서를 영구 파일로 만들지 않는가

# H. 반복 문제 전환

> 같은 원인의 지적이 **3회 이상** 반복되면 명세가 부족한 게 아니라 **접근이 잘못된 것**이다.

- [ ] 같은 누락이 표현만 바뀌어 반복되는가
- [ ] 프롬프트가 길어 핵심 지시가 묻히는가
- [ ] 검증 설계가 구현보다 커졌는가
- [ ] 구현 전 지시와 구현 후 감사가 섞여 있는가

**3회를 넘으면 전환한다.**

| 방향 | 실제 사례 |
|---|---|
| 다른 설계로 갈아탄다 | `--redo`가 "레포 직접 추출 후 복구" → **"임시 디렉터리 선추출"**로 바뀌자 복구 로직이 단순해지고 논의가 끝났다 |
| 범위를 쪼갠다 | 5-A를 구조(5-A-1)와 로직(5-A-2)으로 분리 |
| 직접 코드를 쓴다 | 명세로 설명하는 것보다 코드를 쓰는 게 빠를 때 |

# I. 구현 후 감사

> **교훈** 구현이 끝난 코드에 **구현 전 지시를 반복하지 않는다.**

확인 대상은 명세가 아니라 실물이다.

- [ ] `git diff` · 변경 파일 목록
- [ ] 핵심 구현 코드 — **인용해서** 확인
- [ ] 테스트 코드와 실행 결과
- [ ] 빌드 결과와 검증 스크립트 결과
- [ ] 작업 트리 상태
- [ ] **미실행 또는 실패한 항목**

**원칙**

- 구현 보고서의 주장만으로 통과시키지 않는다.
- 불일치가 발견되면 **파일·행번호·문제 코드·위반 내용**을 보고한다.
- **감사 중 임의로 수정하지 않는다.** 수정은 사용자 승인 후 별도 작업으로.
- 미검증 항목을 완료로 보고하지 않는다.

# J. 외부 검증

> **사고 ⑩** `is:inline`이면 `import`가 실행되지 않는다고 단정했다.
> 실제로는 `type="module"`이 함께 있으면 정상 동작한다. 공식 문서를 안 봤다.

- [ ] 최신 라이브러리 사용법·버전 호환 조건
- [ ] 브라우저·운영체제·도구 지원 여부
- [ ] 보안·개인정보·법률·정책
- [ ] 접근성·웹 표준
- [ ] 정확한 수치나 사실

**원칙**

- 공식 문서를 우선한다.
- **프로젝트 실측 결과가 있으면 일반론보다 우선**한다. 둘이 다르면 함께 보고한다.
- 확인되지 않은 내용을 사실처럼 단정하지 않는다.
- 같은 세션에서 이미 확인한 내용을 다시 검색하지 않는다.
