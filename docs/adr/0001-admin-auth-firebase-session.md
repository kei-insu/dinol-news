# 0001. 운영자 인증을 Firebase Auth 세션으로 전환

| 상태 | 날짜 | 대체 관계 |
|---|---|---|
| 채택 | 2026-07-15 | — |

> 사건 기록은 `docs/issues.md` 2026-07-15 「마스터(운영자) 비밀번호 공개 노출」 행.
> 이 문서는 그 사건에서 **왜 그 방식을 택했나**만 다룬다.

## 배경

`assets/dinol-firebase.js`에 마스터 비밀번호가 상수로 하드코딩돼 있었다. public repo이자 브라우저에서 그대로 조회되므로 **누구나 마스터 비번을 읽어 모든 글/댓글을 수정·삭제 가능**한 상태였다.

원인은 두 가지다. 클라이언트 JS에 인증 비밀을 둔 것, 그리고 마스터 권한 판별을 클라이언트에 위임한 것.

## 결정

운영자 판별을 **Firebase Auth 세션**으로 이전한다.

1. `ADMIN_PW`·`ADMIN_HASH` 상수 제거
2. 운영자 판별을 `onAuthStateChanged` → `IS_ADMIN` 으로 전환
3. 로그인 API `window.dinolAdmin.login/logout` 도입
4. 운영자 아바타(✨) 판정을 해시 대조 → 문서의 `admin:true` 필드 기준으로 변경
5. 비번 입력 6자리 예외를 제거하고 4자리 고정

## 근거

**클라이언트 검증은 UX 편의일 뿐 보안 경계가 아니다.**

브라우저에 내려간 값은 전부 읽힌다. 해시로 바꿔도 대조 로직이 클라이언트에 있는 한 우회된다. 권한 판별은 서버가 검증할 수 있는 신원(Auth 세션 + Firestore 규칙)에 근거해야 한다.

4번이 같은 원리의 적용이다. ✨ 배지가 해시 대조에 걸려 있으면 배지 표시 자체가 클라이언트 판단이 된다. Firestore 문서의 `admin:true` 필드를 기준으로 삼으면 규칙이 검증하는 값과 화면에 보이는 값이 같아진다.

## 검토했으나 버린 안

| 안 | 버린 이유 |
|---|---|
| 비밀번호 값만 교체하고 하드코딩 구조는 유지 | 값 변경이 아니라 **폐기**가 필요하다. 구조를 두면 새 값도 같은 방식으로 노출된다 |
| 노출된 값을 새 Auth 계정 비밀번호로 재사용 | 이미 공개된 값이다. 값은 문서에 기재하지 않는다 |

> 원문에 "검토 후 기각"으로 명시된 것은 위 2건이다. 결정 4·5번은 **대체된 이전 방식**이지 별도로 검토·기각된 대안이 아니므로 여기 넣지 않는다.

## 결과

코드 조치는 완료됐고 `ADMIN_PW`·`ADMIN_HASH` 잔여 참조는 0건이다.

남은 위험·제약 2가지.

- **git 이력에는 노출된 값이 그대로 남는다.** 작업 트리에서 지워도 과거 커밋은 남는다. 근본 해결은 값 자체의 교체이며 노션 백로그 「마스터 비밀번호 값 교체 검토」가 그 항목이다.
- **Firebase 콘솔 설정이 선행돼야 실제로 동작한다.** Auth 이메일/비번 활성화, 운영자 계정 생성, UID를 `firestore.rules`에 반영. 노션 백로그 「Firebase Auth 운영자 계정 설정」 소관.
